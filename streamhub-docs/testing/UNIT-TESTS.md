# StreamHub — Unit & Integration Test Catalogue

## Go core (`streamhub-core-go/`) — the shipped core (3.x)

Run from `streamhub-core-go/`:

```bash
go test ./...                            # every package: unit + integration, no infra
go test -race -count=1 ./internal/edge/  # one package
go vet ./... && gofmt -l .               # CI (core-go job) gates on both
```

**No infrastructure**, by rule: Redis, LiveKit, S3, SMTP, MQTT, ffmpeg and outbound HTTP sit
behind small interfaces with in-memory fakes; SQLite is a real migrated temp `DATA_DIR`
(`internal/platform/testutil`). A test that dials the network is a bug.

**Cross-runtime vectors.** Wherever byte-compatibility with the 2.x core matters (token /
password hashes, AES ciphertexts, JWTs, TOTP, casbin truth table, audit hash chain,
class-validator messages incl. `@Length`, js-yaml dump/load, plugin spawn specs, the edge
WebSocket protocol frames, the MCP server's tool catalogue + zod validation issues) the expected values were **generated by the Node code** into
`testdata/` and are frozen since its retirement — the generating script/snippet sits next to
them, marked HISTORICAL (it needs a `legacy/node-2.x` / tag `2.24.0` checkout) (e.g.
`internal/edge/testdata/record-node-ws.js` boots the Node gateway and records every
master→edge frame; `internal/platform/validate/testdata/gen_length.js`). Each package ports
the invariants of the corresponding Node `*.spec.ts` (the jest catalogue below) into
table-driven Go tests. `internal/plugins` also guards the hand-edited built-in catalog
(`TestBuiltinsCatalogIsValid` over `builtin/builtins.json`; `TestCatalogVector -update`
re-baselines `testdata/catalog.json` for a deliberate change).

**Boot wiring.** `cmd/streamhub/boot_test.go` wires every plane and builds the full handler —
it catches provide/need mismatches and duplicate huma schema names before deploy.
**Guard coverage (3.3.3).** `TestEveryOperationDeclaresItsGuard` walks every registered huma
operation: an `/apps/{app}` / `{name}` one must carry `authz.Require`, any other one must be
`api.Global` — unless it is listed with its reason in `publicByDesign` (every `api.Public` route)
or `scopedByDesign` (caller-scoped by its handler: own account/sessions/team, tenant-filtered
lists, build info…); stale entries fail too. `TestGlobalMarkerMatchesHandlers` parses the module
sources and keeps the declaration honest: a `huma.Register` whose op carries `api.Global` must have
a handler that calls `api.RequireGlobal` (directly or via a package helper), and vice versa. The
findings it surfaced are locked by `internal/streams` `TestHlsRoutesRequirePermission` (A1: HLS
start/stop/status need `stream:start/stop/read` + tenant/app scope), `internal/logs`
`TestGlobalLogsRequireGlobalScope` (A2: `GET /logs` global-only), `internal/quotas`
`TestUsageOtherTenantDenied`, `internal/apps` `TestCreateDeniedToAppScopedToken` and
`internal/authn` `TestTeamsMineDeniedToAppScopedToken` (app-scoped tokens confined on the routes
without an app in the path).
`cmd/streamhub/subcommands_test.go` locks the `seed-token` contract (stdin/argv, default name,
sha256 row, idempotence, revoked tokens ignored).
`internal/samples` `TestCommittedExamplesUpToDate` fails while the committed `examples/` tree
drifts from what `go generate ./cmd/build-examples` writes; `TestHlsPlayerUsesVideoJSBundledVHS`
keeps the standalone `@videojs/http-streaming` out of `hls-player.html` (video.js 8 bundles it).
`internal/platform/config` locks the `PUBLIC_BASE_URL` → `STREAMHUB_PUBLIC_URL` fallback.

### Cameras — OpenCam console (`internal/cameras`, `internal/cameras/opencamsim`)

No sockets: the service runs either on a fake `fleet.Client` (deterministic, fake
clock) or against the **simulator** (`opencamsim.Device`, the same code as
`cmd/opencam-sim`) over `opencamsim.MemBroker`, an in-memory broker with `+`/`#`
filters, retained messages and LWT.
- **protocol** (`TestParseTopic`, `TestValidateCommand`, `TestParseResponse`,
  `TestParseBroker`): topic tree incl. single-segment `res/reboot`, allowlist +
  per-command validation (PTZ dirs, `hold_ms` clamp, sha256, `sd/format` confirm,
  envelope keys stripped), uniform + legacy responses → phases, broker URL →
  host/port/TLS for `config.ini`.
- **service** (`TestInactiveWithoutPluginOrBroker`, `TestInventoryFromMQTT`,
  `TestStaleReapAndApi0Camera`, `TestEventsBoundedDedupAndGap`,
  `TestCommandLifecycle`, `TestLongCommandRebootResolvesOnNewBoot`,
  `TestUpsertAndConfigIni`, `TestWaitForResolution`): subscribe only when enabled +
  mqtt; root change re-creates the client; hello/status/state/thumb/event ingest
  and the summary; retained replays are not live traffic; stale reap; event ring
  bound, `(boot_id, seq)` dedup, gap → `eventsLost` + `events {n}` refill ingested;
  envelope/topic, `if_rev`, caps gate (409), ephemeral `ptz/dir`, dangerous needs
  confirm + audit, `exp + 10 s` timeout and late answers, accepted → progress →
  failed, reboot resolved by a new `boot_id`; alta + `config.ini`; `waitMs`.
- **routes** (`TestRoutes`): every operation's status codes and error texts, the
  typed helpers' published topics, `config.ini` / `thumb` headers, 409 inactive.
- **simulator end to end** (`sim_test.go`, 4): retained-replay discovery,
  done/failed(bad_request, conflict, unsupported) answers, PTZ deadman (moves while
  repeated, stops alone), HD switch, reboot (accepted → `busy` for a second long
  command → LWT offline → new boot → done), OTA progress → new `fw` + `booted`
  event, `expired`, timeout, seq gap refill.

Plus an e2e against a real mosquitto (docker) with `cmd/opencam-sim` — see
[cameras.md](../features/cameras.md#simulator).

### Fleet battery monitor (`internal/fleet`, `battery_test.go`)

Port of the Node `fleet-battery-monitor.service.spec.ts` (unmerged 2.x branch
`feat/hls-direct-serve-scaling`), no DB/MQTT: fake plugin config, agent registry and
callbacks funnel. Locks the per-agent latch: one `fleet.battery_low` on breach (payload +
key order `{agentId, batteryPercent, thresholdPercent}`), no flap inside the 10-point
margin (incl. exactly threshold+10), one `fleet.battery_recovered` past it; never fires
above the threshold; agents without a battery (absent, no telemetry, non-number) are
skipped, never 0 %; threshold `0` / negative / string / plugin disabled / not installed →
the app is skipped without reading the registry; agents independent; a latch is forgotten
when the agent disappears; apps-list / registry errors, a failing funnel and a panicking
registry are logged, never raised (the overlap guard is released); the ticker drives a
pass. `TestBatteryMonitorOverService` wires it over the real `Service` + `fleet.db`
(telemetry → registry → event, `metrics.battery` null on AC-only hosts).
`fleet_test.go` `TestParseTelemetry` covers the battery clamp (0–100) and omission;
`internal/streamflow` `TestCatalogue` asserts the `fleet` event family is in the
catalogue.

### Signed HLS, geo-blocking, play-auth — G2 3.4.0 (`internal/playback`, `internal/platform/web`)

No network: fake apps/config, an in-process `http.RoundTripper` for the webhook, a fake
country lookup, and a MaxMind DB **built in the test** (`geo_test.go` `buildMMDB`).
- `internal/playback/token_test.go`: `st` round-trip and shape; bound to app, room dir
  and exp (tampered app/dir/exp/MAC/garbage → invalid, never expired); expired only once
  authentic; another secret / no secret verifies nothing; the key is the labelled HMAC
  of the secret (pinned: changing it breaks every issued token); length-prefixed
  encoding cannot be re-split (`a|1:b`/`c` ≠ `a`/`b|1:c`).
- `geo_test.go`: `CheckGeo` matrix (no policy / empty lists / no base = off; allow
  hit/miss; unknown and garbage IPs fail closed under an allowlist, pass under a deny
  list; deny wins; loopback/LAN/IPv4-mapped LAN never blocked); `GeoIP` over a real
  `.mmdb` (IPv4 + mapped, `registered_country` fallback, IPv6 against an IPv4 base and
  unknown nets not found, garbage/missing file refused).
- `guard_test.go`: `AuthorizeHLS` (public passes; unknown app never reaches the
  registry; private without/with bad token 403; minted token 200 and `Private`+`Token`;
  token reused on another room 403; expired 403 `HLS token expired`; geo by the
  right-most `X-Forwarded-For`; unreadable config denies; policy cached per app);
  `MintHLS` (public → none, private → app TTL, no secret → 503, unknown app → error);
  `CheckPlayback` (geo deny/pass; webhook body/headers/HMAC signature, 2xx grants,
  403/302/500 deny, transport error denies unless `fail_open`, private webhook target
  refused by the SSRF guard without dialling); `CheckPublish` (`publish:true` only).
- `internal/platform/web/hls_gate_test.go`: the G2 "hecho" end to end on the real mount —
  private app without/with bad token → 403 on playlist, segment and a missing segment
  (no existence oracle), `no-store`; with token → 200, playlist rewritten (segments +
  `EXT-X-KEY`), `private` cache headers, HEAD ok, OPTIONS never gated; public apps
  byte-identical; no gate = pre-3.4 mount. `/hls-auth`: 204/403 by `X-Original-URI` or
  `X-Forwarded-Uri`, the `../` traversal judged on the normalized path (never borrows a
  public app's verdict), dotfiles/non-HLS/garbage/no header → 403, scope header.
  `TestRewritePlaylist`: relative/root-relative URIs and `URI="…"` attributes get the
  token (`?`/`&`, before `#`), absolute/`//`/`skd:` URIs and CRLF untouched.
- `internal/livekit/playback_test.go`: play/listen-token run the guard (mode, `?token=`
  forwarded) and its 403 keeps the CORS header; an unsigned private request is refused
  before the guard; `GET hls-token` (public → `required:false`; private needs the signed
  URL, returns `st` + tokenized `playlistUrl`, other room 403, unknown app 404, no guard
  503); the sign endpoint carries `hlsToken`/`hlsUrl` only for private apps.
- `internal/streams/hls_signed_test.go`: `playlistUrl` of start/status tokenized only for
  private apps, minted for the on-disk room dir.
- `internal/passthrough/hooks_geo_test.go`: MediaMTX auth hook with `publish:true` → 401
  for a blocked publisher IP, only for an otherwise authorized passthrough key.
- `internal/apps/resolve_g2_test.go`: `hls_token_ttl_seconds` clamp, `geo` list
  sanitizing (upper-case, dedupe, invalid dropped), `play_auth` defaults/clamp, and the
  three blocks omitted from the JSON when unset.

## Auth / Tenancy / Authz / Quotas (144 tests)

### `auth.service.spec.ts` — 45
The credential resolver: signup/login, `sk_` API tokens, IP whitelisting, login
JWTs and the public-path bypass.

Invariants:
- **Signup** creates user + team + owner membership and mints a valid JWT;
  duplicate email rejected; a PENDING (invited, password-less) user can complete
  signup keeping their team; refuses when `STREAMHUB_JWT_SECRET` is unset;
  cannot sign up as the configured `ADMIN_USER` email.
- **Login** validates password; rejects wrong/unknown/pending; **break-glass
  admin** (`ADMIN_USER`/`ADMIN_PASS`) mints an admin JWT (`sub=admin`) and is
  only enabled when creds are set.
- **`sk_` tokens**: a global token → superadmin/global (back-compat); an
  app-scoped token → non-superadmin service (`scope=app`); unknown/revoked/
  missing rejected; `last_used_at` touched on success.
- **IP whitelist**: exact + CIDR match, rejects outside, honours
  `X-Forwarded-For` over socket IP, normalises IPv4-mapped IPv6, empty
  whitelist = no restriction.
- **Login JWTs** resolve user → tenant + role; admin JWT → superadmin (never
  lockable, even with `ADMIN_USER` unset); expired / wrong-secret / unknown-sub
  rejected.
- **Public-path bypass** (`it.each`): `/api/v1/play/**`, `/embed`, health/docs
  paths resolve to `PUBLIC_CONTEXT`; a non-public path does not.
- **Token management**: plaintext returned once, only a hash stored; `appId`
  required for `scope=app`; rejected on global tokens; list never leaks the
  hash; revoking a non-existent token rejected.

## Streams — including the duplicate-stream regression (29 + 8 e2e) + HLS cache (11) + pipeline topology (13 + 2)

### `streams.service.spec.ts` — 29
The stream-tracking core. **The canonical key is `${room}/${identity}`** — the
single key shared by the webhook path and the reconcile path. This is the fix
for the over-counting bug.

- **`canonicalStreamId` invariant**: id is exactly `${room}/${identity}`.
- **upsert**: one active row per new canonical stream; idempotent on the
  canonical key (`ON CONFLICT` → single row); **never downgrades an ingress type
  back to webrtc** (webhook order-independent); reactivates an ended row;
  NotFound for unknown app.
- **REGRESSION — one RTMP ingress must be ONE stream, not three**:
  `ingress_started` + `participant_joined` + reconcile collapse into a **single
  active row**; reconcile alone (no webhook) creates the same canonical row.
  *(This is the guard against the bug where subscribers/participants inflated the
  stream count.)*
- **list() reconcile — discovery + dedupe**: distinct live publishers, no
  duplicate ids; a viewer (non-publisher) never creates a stream; pre-existing
  webhook row + reconcile discovery of the same publisher stays one row; only
  active rows returned.
- **reconcile prune**: ends aged active rows whose participant stopped
  publishing or whose room is gone; does NOT prune within the grace window; does
  NOT prune when the participant list can't be fetched (state unknown); no-op
  when LiveKit unreachable; ends legacy non-canonical rows (id without `/`);
  when no `roomClient` configured, `list()` returns active rows untouched.
- **ws-mjpeg exemption (ESP32-WS-INGEST)**: reconcile NEVER prunes
  `type='ws-mjpeg'` rows (their liveness is owned by the ws-ingest gateway, not
  LiveKit) while a normal aged rtmp row in the same run IS pruned; upsert never
  downgrades `ws-mjpeg` back to `webrtc`.
- **get()**: null for unknown; returns record; exposes viewer count (**real
  subscribers only**) when `viewerCounter` enabled, hides it otherwise.
- **stop()**: NotFound unknown; disconnects participant + marks webrtc ended;
  no LiveKit teardown for an already-ended stream.
- **snapshot() guards**: blank room → 400; unknown app → 404.

## Worker desired-state + boot-resume (survives a core restart)

A needsWorker plugin's process must SURVIVE a core restart/deploy — otherwise
lpr/perimeter/presence silently stop detecting after every upgrade. A persisted
`app_plugins.worker_desired` ('running'|'stopped'|NULL) records operator intent;
a best-effort boot-resume restarts what was running. Coverage (extended suites):

### `modules/plugins/app-plugins.repository.spec.ts` (+4)
The `worker_desired` column: defaults NULL on a fresh install; `setWorkerDesired`
round-trips on `get`/`list`; a no-op on an unknown plugin; and the column is
**added idempotently** to a legacy app.db that predates it (drop-column →
first repo access re-adds it, no throw).

### `modules/plugins/plugins.service.spec.ts` (+6)
Desired-state transitions across the lifecycle — install → `stopped`, enable →
`running`, explicit stop → `stopped`, explicit start → `running`, disable →
`stopped`. Boot-resume (`resumeDesiredWorkers`): restarts a worker whose intent
is `running` after its process was killed (idempotent — a second call starts 0),
does NOT restart one the operator explicitly stopped, and **backfills** a NULL
intent conservatively (enabled needsWorker → `running` + start, disabled →
`stopped` + leave down), persisting the derived intent. Uses the real `sleeper`
worker fixture + real repo (no mocks).

### `modules/vision-apps/vision-migration.service.spec.ts` (+1)
The vision→apps migration marks the migrated ENABLED model-apps
`worker_desired='running'` so the boot-resume brings their detection back after
the 2.16.0 deploy (the migration also triggers a scoped resume via the optional
PluginsService — the global resume skips the retired `vision` install since its
meta is gone).

## Cross-cutting invariants this suite locks

- **One publisher = one stream.** Canonical key `${room}/${identity}`; webhook
  and reconcile converge on a single row; viewers/subscribers never create
  streams. (The over-count regression is pinned.)
- **Tenant isolation.** Apps home to a tenant; cross-tenant reads/actions are
  403 under AUTHZ=on; a fresh app is homed to platform.
- **Superadmin / sk_ / unscoped never locked out.** Enforced across off/log/on
  modes and quotas.
- **Secrets never leak.** Credentials masked in responses, never written to
  YAML; token plaintext returned once, only hashes stored; S3 errors don't leak
  secrets.
- **Webhooks always ack 200; callbacks never throw.** Delivery retries are
  bounded and swallow failures.
- **VOD safety.** Upload failure keeps the local file; delete cascades S3 + local
  + row; recordings drain fully on purge.
- **Config editor is fail-safe.** A bad YAML never overwrites a good one; every
  PUT is backed up (≤20) and revertible.
